# 批次开工与验收清单

依据 [文件整理执行规程](../docs/执行规程.md)。预演时把实际文件动作一栏标为不适用。

## 开工

- [ ] 批次号、日期、时区、规程版本和执行工具已记录。
- [ ] 扫描根、深度、目标、排除项与记录目录已写明。涉及续批时，已注明验收后基线及目录迁移或扫描口径变更。
- [ ] 版本、分类、命名分别标记本次处理范围。
- [ ] 已读本批项目说明，已记录活跃区、保护路径与复查条件。
- [ ] 已生成只读基线，读取失败、链接和不可访问范围有据可查。

## 计划

- [ ] 每项均有源路径、读取范围、理由、指纹及建议状态。
- [ ] 复制归档有落点；版本或重复回收候选有最终留存者。
- [ ] 已检查落点冲突、引用影响与回收指向环，拿不准的对象继续保留。
- [ ] 已区分预演、待确认、待批准与实际执行。

## 实际文件动作

- [ ] 本批明确获批；移入归档采用暂存、校验、不覆盖提交。同内容目标核验后跳过，同名异内容记录冲突。
- [ ] 逐卷核实实际回收站配额和剩余量，并用本批样本验证真实恢复。只有估值或未能核实配置则开工受阻，样例保留。
- [ ] 每个拟变更项已重验适用的项目规则和活跃状态。回收中间产物前已核成品、重建证据及剩余引用。
- [ ] 逐项核实回收留存者、源卷、双方指纹和实际恢复实体，证据不足则停止该卷后续回收。Windows 按原路径、动作时间和对应内容实体匹配本批条目，单列仅残留的索引。
- [ ] 逐项保存结果与证据，失败或不明结果未计入完成。失败暂存件和空暂存目录保留原位并登记。重跑时核对目标路径、指纹和修改时间。

## 验收

- [ ] 重新枚举，对照前后路径、成员和指纹。
- [ ] 逐项核对已变更的文件、引用和缺失原路径的去向。改名日志区分动作前后状态，文本引用只改获批路径并实际打开验证。对照落盘结果检查成功状态，发现矛盾须保留原始记录并单列。
- [ ] 报告区分源目录、归档库、未扫描范围、未解决项。
- [ ] 台账与实物按事先记录的同一范围核对，范围外和读不到的记录已单列。每条索引变更对应已验证动作，暂存表核对通过后才替换，前后差异可追溯。
- [ ] 前后快照、计划、日志、结果和未决项已留在批次记录目录。
